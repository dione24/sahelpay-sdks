---
title: Créer un abonnement
api: POST /v1/billing/subscriptions
description: "Identité sans téléphone, essai explicite et checkout"
---

`POST /v1/billing/subscriptions/with-payment` crée un abonnement et le premier
lien de paiement. `POST /v1/billing/subscriptions` prépare seulement le calendrier.
Voir le [guide Billing bilingue](/guides/subscriptions) pour les périodes payées et les essais explicites.

| Champ | Requis | Description |
| --- | --- | --- |
| `plan_id` | Oui | Plan actif dans l'application et le mode de la clé |
| `customer_id`, `customer_external_ref`, `customer_email`, `customer_phone` | Au moins un | Téléphone facultatif |
| `customer_name` | Non | Nom du client |
| `trial_end` | Non | Fin d'essai ISO UTC future ; checkout sans facture/lien pendant l'essai |
| `start_date` | Non | Première échéance ; création simple uniquement |
| `external_ref` | Non | Référence stable de checkout ; avec `customer_external_ref`, sans ID/téléphone |
| `redirect_url`, `metadata` | Non | Checkout uniquement |

```typescript
const result = await api.subscriptions.createWithPayment({
  plan_id: 'PLAN_ID', customer_external_ref: 'test_user_PLACEHOLDER',
  external_ref: 'test_checkout_PLACEHOLDER', idempotency_key: 'test_checkout_PLACEHOLDER',
});
// result.invoice et result.payment_link peuvent être null.
```

L'option SDK `idempotency_key` est un en-tête, pas un champ JSON. Consultez les
garanties de rejeu dans le guide. Les deux créations exposent `trial_end`,
`current_period_start/end` et `next_billing_date`. Sans essai ni paiement : INCOMPLETE.
Une création d’essai conserve ACTIVE avec trial_end ; son GET canonique est
TRIALING. ACTIVE canonique signifie une période payée courante.

Erreurs : 400 validation/plan inactif, 404 plan absent ou hors périmètre, 409 conflit.
