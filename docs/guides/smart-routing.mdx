# Méthodes de paiement

Vous spécifiez la méthode de paiement souhaitée par votre client, et SahelPay
choisit le gateway interne correspondant.

<Warning>
  **Orange Money (Mali) est le seul rail intégré aujourd'hui.** Toute autre valeur
  de `provider` est rejetée avec une erreur `400`. Wave, Moov et les cartes
  bancaires sont en feuille de route et ne sont pas encore disponibles.
</Warning>

## Méthodes disponibles

| Méthode | Statut | Pays | Capacités |
|---------|--------|------|-----------|
| `ORANGE_MONEY` | ✅ Disponible | Mali | Paiements, Payouts |

Les alias `ORANGE` et `MOBILE_MONEY` sont acceptés et résolus vers `ORANGE_MONEY`.

## Interrogez la liste, ne la codez pas en dur

Les rails activés évoluent. Plutôt que de figer une liste dans votre code,
demandez-la à l'API :

```bash
curl https://api.sahelpay.ml/v1/providers/enabled
```

```json
{
  "success": true,
  "data": [
    {
      "provider": "ORANGE_MONEY",
      "display_name": "Orange Money",
      "category": "MOBILE_MONEY",
      "min_amount": null,
      "max_amount": null
    }
  ]
}
```

C'est cette liste qui alimente le checkout hébergé. En la consommant, votre
intégration prendra en charge un nouveau rail sans que vous ayez à redéployer.

## Informations de routing

Chaque paiement retourne le gateway retenu :

<CodeGroup>

```typescript JavaScript
const payment = await sahelpay.payments.create({
  amount: 5000,
  payment_method: 'ORANGE_MONEY',
  customer_phone: '+22370123456',
});

console.log(payment.gateway_used);    // Identifiant technique interne
console.log(payment.routing_reason);  // Explication du routing choisi
```

```python Python
payment = client.payments.create(
    amount=5000,
    provider='ORANGE_MONEY',
    customer_phone='+22370123456'
)

print(payment.gateway_used)    # Identifiant technique interne
print(payment.routing_reason)  # Explication du routing choisi
```

</CodeGroup>

<Note>
  Ces champs sont **informatifs** et destinés au support. Vous ne choisissez pas
  le gateway : SahelPay le résout à partir de la méthode demandée.
</Note>

## Disponibilité d'un rail

Un rail peut être désactivé ou mis en maintenance côté administration. Dans ce
cas, une demande de paiement sur ce rail échoue avec un `400` explicite plutôt
que d'être routée ailleurs en silence.

Ces changements s'appliquent sans redéploiement, d'où l'intérêt de lire
`/v1/providers/enabled` au moment d'afficher les options à votre client.
