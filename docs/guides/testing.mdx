# Tests

La sandbox est **gratuite** et ne demande aucun abonnement. Testez toute votre intégration avant de passer en production.

## Environnement sandbox

| | Sandbox | Production |
|---|---------|------------|
| **URL** | `https://api.sahelpay.ml` | `https://api.sahelpay.ml` |
| **Clés** | `sk_test_xxx` | `sk_live_xxx` |
| **Abonnement SahelPay** | Non requis | Payé et en cours |
| **Transactions** | Sandbox Orange ou simulateur SahelPay | Réelles, plafonnées par le forfait |

Le sandbox est un mode logique porté par la clé `sk_test_...`. N'utilisez pas de base URL différente pour les SDK. Un compte sans abonnement payé fonctionne entièrement en sandbox.

## Deux modes de test

| Metadata | Option SDK | Effet |
|----------|------------|-------|
| `sandbox: true` | `sandbox` | Appelle l'**environnement de test d'Orange**. Valide l'intégration de bout en bout. |
| `sahelpay_mock: true` | `mock` | Utilise le **simulateur SahelPay**. Aucun appel opérateur. |

Ces métadonnées sont réservées aux clés de test : en production, elles sont refusées avec une erreur `400`.

## Simulateur SahelPay

Avec `sahelpay_mock: true`, le statut final est piloté par le montant :

| Montant | Comportement |
|---------|--------------|
| `4000` | Paiement réussi |
| `4001` | Paiement échoué (solde insuffisant) |
| `4002` | Paiement en attente |
| `4003` | Paiement échoué (erreur opérateur) |
| Autre montant valide | Paiement réussi |

La simulation démarre à l'initiation du paiement. Utilisez donc `hosted_checkout: false` (initiation immédiate), puis appelez `GET /v1/payments/{id}/status` : SahelPay applique le statut simulé et émet le webhook correspondant.

```bash
curl -X POST https://api.sahelpay.ml/v1/payments \
  -H "Authorization: Bearer sk_test_xxx" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: test-4000-1" \
  -d '{
    "amount": 4000,
    "currency": "XOF",
    "payment_method": "ORANGE_MONEY",
    "customer_phone": "+22370123456",
    "client_reference": "order_test_1",
    "hosted_checkout": false,
    "metadata": { "sahelpay_mock": true }
  }'

curl https://api.sahelpay.ml/v1/payments/<id>/status \
  -H "Authorization: Bearer sk_test_xxx"
```

<Note>
  Avec `hosted_checkout: true` (défaut des SDKs), le paiement reste `INITIATED` jusqu'à ce que le client
  ouvre le checkout : la simulation ne s'applique qu'à partir de ce moment.
</Note>

## Tester les webhooks

### Avec un tunnel (local)

```bash
# Exposer votre serveur local
ngrok http 3000

# Configurer l'URL dans le dashboard
# https://xxxx.ngrok.io/api/webhooks/sahelpay
```

### Déclencher un webhook manuellement

```bash
curl -X POST https://api.sahelpay.ml/v1/webhooks/test \
  -H "Authorization: Bearer sk_test_xxx"
```

Cet endpoint envoie un événement `webhook.test` vers l'URL webhook configurée dans le dashboard. Pour un vrai `payment.success` ou `payment.failed`, utilisez le simulateur ci-dessus.

En sandbox, `GET /v1/webhooks/events` liste les derniers événements émis pour votre compte (utilisé par la CLI de test).
