# Webhooks

Les webhooks vous notifient en temps réel des changements de statut. Configurez l'URL (HTTPS, publique) et récupérez le secret `whsec_...` dans le dashboard. Sans secret configuré, SahelPay n'envoie aucun webhook.

<Warning>
  **Le webhook est la source de vérité.** Ne marquez jamais une commande comme "payée" sans avoir reçu et vérifié un webhook `payment.success`.
</Warning>

## Événements

### Paiements

| Événement | Description |
|-----------|-------------|
| `payment.success` | Paiement confirmé |
| `payment.failed` | Paiement échoué |
| `payment.pending` | Paiement en attente de confirmation opérateur |
| `payment.expired` | Paiement expiré, quelle qu'en soit la cause : délai écoulé, expiration manuelle (`POST /v1/payments/{id}/expire`) ou réconciliation |
| `payment.updated` | Autre changement de statut |
| `webhook.test` | Test de connectivité envoyé par `POST /v1/webhooks/test` |

<Note>
  Aucun événement `payment.cancelled` n'est émis aujourd'hui.
</Note>

### Autres

| Événement | Description |
|-----------|-------------|
| `invoice.created`, `subscription.payment_due`, `invoice.paid`, `subscription.renewed` | [Abonnements clients](/guides/subscriptions) |


## Format du payload (paiement)

```json
{
  "id": "evt_1759480000000_9f2c4e1a7b3d5c60",
  "event": "payment.success",
  "version": "v1",
  "timestamp": "2026-10-03T10:05:00.000Z",
  "data": {
    "id": "8d6f1c2e-...",
    "reference_id": "order-123",
    "client_reference": "order-123",
    "amount": 5000,
    "amount_charged": 5000,
    "currency": "XOF",
    "status": "SUCCESS",
    "provider": "orange_webpay_ml",
    "customer_phone": "+22370123456",
    "metadata": {
      "description": "Commande #123"
    },
    "dashboard_url": "https://app.sahelpay.ml/dashboard/transactions/8d6f1c2e-...",
    "created_at": "2026-10-03T10:00:00.000Z",
    "updated_at": "2026-10-03T10:05:00.000Z"
  }
}
```

- `data.id` est l'identifiant du paiement SahelPay ; `data.reference_id` vaut votre `client_reference`, ou l'`id` à défaut.
- `data.metadata` ne contient que `description` et `marketplace` : vos métadonnées personnalisées ne sont pas renvoyées. Utilisez `client_reference` pour retrouver votre commande.

## Headers

| Header | Description |
|--------|-------------|
| `X-SahelPay-Signature` | `t=<timestamp>,v1=<signature>` |
| `X-SahelPay-Timestamp` | Timestamp UNIX (secondes) |
| `X-SahelPay-Event-ID` | ID unique de l'événement (= `id` du payload) |
| `X-SahelPay-Signature-Algorithm` | `HMAC-SHA256` |
| `X-Request-ID` | Identifiant de corrélation |
| `User-Agent` | `SahelPay-Webhook/1.0` |

## Vérification de signature

`v1 = hex(HMAC_SHA256(webhook_secret, "<t>.<corps brut>"))`. Vérifiez toujours sur le **corps brut** reçu, avant tout parsing JSON.

<CodeGroup>

```javascript Node.js
import crypto from 'crypto';

function verifyWebhook(rawBody, signatureHeader, secret) {
  const parts = {};
  signatureHeader.split(',').forEach(p => {
    const [key, value] = p.split('=');
    parts[key] = value;
  });

  const timestamp = parts['t'];
  const signature = parts['v1'];
  if (!timestamp || !signature) return false;

  // Protection replay (5 min)
  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - parseInt(timestamp, 10)) > 300) {
    return false;
  }

  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${timestamp}.${rawBody}`)
    .digest('hex');

  return signature.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}
```

```python Python
import hmac
import hashlib
import time

def verify_webhook(raw_body, signature_header, secret):
    parts = dict(p.split('=', 1) for p in signature_header.split(','))
    timestamp = parts.get('t')
    signature = parts.get('v1')
    if not timestamp or not signature:
        return False

    # Protection replay
    if abs(time.time() - int(timestamp)) > 300:
        return False

    payload = f"{timestamp}.{raw_body}"
    expected = hmac.new(secret.encode(), payload.encode(), hashlib.sha256).hexdigest()
    return hmac.compare_digest(signature, expected)
```

```php PHP
function verifyWebhook($rawBody, $signatureHeader, $secret) {
    $parts = [];
    foreach (explode(',', $signatureHeader) as $part) {
        [$key, $value] = explode('=', $part, 2);
        $parts[$key] = $value;
    }

    $timestamp = $parts['t'] ?? null;
    $signature = $parts['v1'] ?? null;
    if (!$timestamp || !$signature) {
        return false;
    }

    // Protection replay
    if (abs(time() - (int)$timestamp) > 300) {
        return false;
    }

    $expected = hash_hmac('sha256', "{$timestamp}.{$rawBody}", $secret);
    return hash_equals($expected, $signature);
}
```

</CodeGroup>

Les SDKs le font pour vous : `sahelpay.webhooks.constructEvent()` (JS), `client.webhooks.construct_event()` (Python), `$sahelpay->webhooks->constructEvent()` (PHP).

## Retry automatique

En cas d'échec (réponse non 2xx ou timeout), SahelPay retente avec un backoff exponentiel :

| Tentative | Délai |
|-----------|-------|
| 1 | Immédiat |
| 2 | 1 minute |
| 3 | 2 minutes |
| 4 | 4 minutes |
| 5 | 8 minutes |

Après 5 tentatives, le webhook est marqué comme `FAILED`. Vous pouvez consulter les livraisons et relancer depuis le dashboard ou via `GET /v1/webhooks/logs` et `POST /v1/webhooks/logs/{id}/retry`.

## Tester les webhooks

<CodeGroup>

```bash cURL
curl -X POST https://api.sahelpay.ml/v1/webhooks/test \
  -H "Authorization: Bearer sk_test_xxx"
```

```typescript Node.js
await sahelpay.webhooks.test();
```

```python Python
client.webhooks.test()
```

```php PHP
$sahelpay->webhooks->test();
```

</CodeGroup>

Cet appel (5 par minute au maximum) envoie `webhook.test` vers l'URL configurée. Pour recevoir un vrai `payment.success` ou `payment.failed` sans appel opérateur, créez un paiement simulé (`metadata.sahelpay_mock: true`, `hosted_checkout: false`) puis appelez `GET /v1/payments/{id}/status` : voir [Tests](/guides/testing).

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Répondre rapidement">
    Répondez `200 OK` en quelques secondes. Si le traitement est long, faites-le en asynchrone.
  </Accordion>
  <Accordion title="Gérer l'idempotence">
    Un même événement peut arriver plusieurs fois : dédupliquez sur `X-SahelPay-Event-ID` (ou `id` du payload).
  </Accordion>
  <Accordion title="Ne pas suivre de redirection">
    SahelPay n'en suit aucune : votre endpoint doit répondre directement, en HTTPS, sur une adresse publique.
  </Accordion>
</AccordionGroup>
